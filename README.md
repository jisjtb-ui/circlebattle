# CIRCLE BATTLE

TikTok LIVE 連動のバトルゲーム。

```
        【自動生成される敵】
                VS
        【TikTok LIVE 視聴者】
```

視聴者が **LIKE / FOLLOW / SHARE / GIFT** をすると、その人専用の円が生まれ、**育ちます**。
円は自動生成される敵を攻撃し、倒した数とスコアで **TOP 10 PLAYER** を競います。

円は増えません。**1 人 1 つの円に、行動ごとに別の力が付いていく**形です
(→ [2. 視聴者から見たルール](#2-視聴者から見たルール))。

チームはありません。`Team A` / `Team B` のような固定の陣営概念は 1 つも実装していません。
並ぶのは常に個人です。

TikTok の接続部分は **KAWAII VS BEAUTIFUL / tikhub で作ったものをそのまま使います**
(→ [11. 既存システムとの関係](#11-既存システムとの関係))。

## 1. 動かす

`index.html` をブラウザで開き、**[ OPEN GAME WINDOW ]** を押します
(`file://` でも動きます)。画面は 2 つに分かれています。

```
   index.html                       game.html
   操作画面 (触る)                    ゲーム画面 (配信に映す)
   ─────────────                    ──────────────
   LIVE の URL / CONNECT             Game Status
   BGM (MP3) / 音量                  Battle Field
   ゲーム・敵・イベントの設定           TOP 10 PLAYER
   テストパネル                       LIVE EVENT
   小さいプレビュー
        │
        └── [ OPEN GAME WINDOW ] ──────┘
              同じゲームを見せるだけ
```

**ゲームは 1 つだけです。** ゲーム画面は別プロセスではなく、操作画面が持っている
ゲームを読んで描いているだけなので、音量も設定も接続も、変えた瞬間に向こうへ届きます。

- 操作画面を**読み込み直す**と、あちらのゲームは作り直されます。ゲーム画面は
  それを見張っていて、自動で新しいほうへ繋ぎ直します
  (`RECONNECTED TO CONTROL WINDOW` と出ます)。ボタンを押し直す必要はありません。
- 操作画面を**閉じる**とゲームも終わります。ゲーム画面には
  `CONTROL WINDOW CLOSED` と出るので、止まったことがすぐ分かります。

> **`game.html` を別のタブや OBS のブラウザソースで直接開くと、それは
> 「もう 1 つの別のゲーム」になります。** ボタンから開いたときだけ状態を
> 共有できるためです (別プロセスとは中身を共有できません)。
> 配信では、ボタンから開いたゲーム画面を **ウィンドウキャプチャ** してください。

OBS では **ゲーム画面をウィンドウキャプチャ**してください (9:16 の縦画面です)。
ブラウザソースを使う場合は `game.html` を直接指定します。この場合は opener が
いないので、その画面が自分でゲームを動かします。

| URL | 用途 |
| --- | --- |
| `index.html` | 操作画面 |
| `index.html?game=1` | 開いた直後にゲーム画面も開く |
| `index.html?offline=1` | TikTok に繋がない |
| `index.html?demo=0` | デモ視聴者を出さない |
| `index.html?sound=0` | 効果音を鳴らさない (`?mute=1` も同じ) |
| `index.html?sort=kills` | ランキングの基準を変える (`score` / `kills` / `damage`) |
| `game.html` | ゲーム画面 (OBS のブラウザソース用。単独で動きます) |
| `game.html?bg=<URL>` | 背景に 1080×1920 の画像を敷く |

**TikTok の実配信と繋ぐ場合**は tikhub を起動し、出てくる URL を開きます
(→ [11.3](#113-tikhub-から配信する))。

ルールのテスト:

```
npm test     # 233 件。ブラウザ不要
npm run check
```

## 2. 視聴者から見たルール

**円は 1 人 1 つ。行動すると、その円に「別々の力」が付きます。**

| 操作 | 付く力 | 何ができるようになるか |
| --- | --- | --- |
| **いいね 10 回** | **HP +70** | 硬くなって盤面に残れます。棘も強くなります |
| **ギフト** | **攻撃力 +6 / コイン** | 殴る力。**武器**もここで育ちます |
| **シェア** | **ドレイン +5%** | 与えたダメージのぶん自分が回復します |
| **フォロー** | **スパイク +3 本** | 360° の棘。触れてきた相手を刺し返します（1 人 1 回だけ） |
| **入室** | HP +3 ポイント・棘 1 本 | 大砲から撃ち出され、金色の輪で光ります（1 人 1 回だけ） |
| コメント | 何も起きません | 将来のコマンド用に受け取るだけ |

### なぜレベルをやめたのか

以前は「レベル 1 〜 100」の 1 本でした。1 本しかないと、**いちばん多く上げ
られる行動（＝ギフト）が全部の面で勝ち**、他の行動は「同じものの遅い版」に
なります。

行動ごとに別の力にすると、それぞれに役割ができます。

```
いいね + フォロー   硬くて、触れた相手を刺す壁    ← 1 円も要りません
ギフト              武器が育ち、遠くまで届く
シェア              長く殴り合うほど強い
```

**タダでも強くなれる道が残ること**をいちばん大事にしました。棘の威力は
**自分の最大 HP から出る**ので、いいねを押してフォローするだけで、
それ自体が一つの完成した戦い方になります。

### それぞれの上限

| 力 | 1 ポイント | 上限 | 上限に要る行動 |
| --- | --- | --- | --- |
| HP | +70 | +9,000 | いいね約 1,290 回 |
| 攻撃力 | +6 | +900 | 150 コイン |
| ドレイン | +5% | 50% | シェア 10 回 |
| スパイク | 棘 1 本 | 12 本 | フォロー + 入室 |

上限があるのは、**大きなギフトを続けた 1 人が誰にも倒せなくなると、
他の全員の行動が意味を失う**からです。

### 視聴者どうしでも戦います

敵を狩るだけでなく、**円どうしがぶつかると削り合います**。

- 威力は敵と殴り合うときの **3 割**。一瞬で溶けないよう抑えてあります
- 棘は殴る / 殴らないに関係なく、**触れているだけで刺さります**
- 倒すと点が入りますが、**相手が貯めたぶんに比例**します。
  入りたての円を狩ってもほとんど点になりません
- 倒された人は円が消えます。**次に何か行動すれば、貯めた力をそのまま持って
  もう一度大砲から撃ち出されます**（貯めた力は死んでも減りません）

10 分・100 人で回した実測です。

| 種類 | 行動 | 平均スコア |
| --- | --- | --- |
| いいねだけ | いいね | 約 950 |
| いいね + フォロー | いいね・フォロー | 約 2,040 |
| いいね + シェア | いいね・シェア | 約 1,240 |
| ギフト中心 | ギフト | 約 3,930 |

ギフトがいちばん強いですが、**フォローしたタダの視聴者が 2 番手**に付けます。

### フィールドが広がる

混んでくると**フィールドが 2 秒かけて広がり**（画面はズームアウト）、空いてくると
また元に戻ります。広がるときは画面中央に英語で知らせが出ます。

```
   STAGE EXPANDED
MORE ROOM – STAGE 2 ×1.35
```

- 判定は「円と敵が床面積のどれだけを占めているか」です。数ではなく面積で見るのは、
  育った円が大きいからです（よく育った円は新入りの約 6 倍の面積）
- 占有率 30% 超で 1 段階広がり、12% 未満で 1 段階戻ります。最大 3 段階（×2.46）
- 中にいるものの座標も一緒に広がるので、**位置関係は変わりません**。
  半径と速さは変わらないので、広いほど散らばって見えます
- 一度変化したら 4 秒は次の判定をしません（行ったり来たりの防止）
- 止めたいときは `field.expand.enabled: false`

### 円は 1 人 1 つだけ

何度行動しても円は増えません。**その 1 つが強くなります。**

何個も並べられると、連打した人だけで画面が埋まります。1 つに絞れば、
行動は「増やす」ではなく「育てる」になります。

大砲が撃つ前にもう一度行動した場合は、大砲の中の 1 発に足されます
（円が 2 つになることはありません）。

### 円は大砲から出てくる

**視聴者の円は、フィールドの端の PLAYER CANNON から撃ち出されます。**
LIKE でも FOLLOW でも SHARE でも GIFT でも入室でも、どれも同じです。
どこかにぽんと現れるのではなく大砲から飛び込んでくるので、
「今この人が入ってきた」というつながりが画面から読み取れます。

```
① 待機        小さい大砲が置いてある
② 装填 0.43秒  拡大・発光、砲口にアイコンと @ユーザー名
              (入室のときは NEW PLAYER / ENTERED THE BATTLE)
③ 発射 0.14秒  閃光・衝撃波・煙・粒。ここで円が生まれる
④ 飛行 0.43秒  尾を引いて中央へ。この間は戦わず、ぶつからない
⑤ 参戦        普通の円として戦い始める
```

1 発およそ 0.74 秒です。**通常時も大砲は消しません。**
「ここから入ってくる」と初見でも分かるほうが、少し場所を空けるより大事なためです。

**何人が一度に来ても、ゲームは止まりません。** 順番待ちに積んで 1 発ずつ撃ちます。

| 待っている数 | どうなるか |
| --- | --- |
| 3 未満 | 通常 (1 発 0.74 秒) |
| 3 以上 | 装填を縮めて急ぐ (1 発 0.28 秒) |
| 14 を超えた | 演出を飛ばして即発射 (出る場所と向きは大砲のまま) |

最後の 1 つがあるので、**入れなくなる人は出ません。**
演出の見栄えより、入れることを優先しています。

100 人が同時に操作した状態でも、待ちの最大は 6、取りこぼし 0、
円は 99 個、撃破ペースも大砲を入れる前と同じでした。

### 入ってきた瞬間、真ん中に名前が出る

**入室を受け取ったその瞬間**に、画面の真ん中へ大きく名前を出します。

```
        @sakura_dance
             JOIN
```

円が出るのは大砲が撃ったあと（混んでいれば数秒あと）なので、円だけに
任せると「今わたしが入った」が画面に出るまで間があきます。名前は円とは別に、
届いたその場で出ます。

目立たせつつ邪魔にしないために、こうしてあります。

- **板を敷かず、暈しと文字だけ。** 出ている間も盤面が透けて見えます
- **1.1 秒で消えます。** 出しっぱなしにすると盤面が見えません
- **1 度に 1 人ずつ。** 重ねると、結局どの名前も読めません
- **混んだら 0.52 秒に縮めます。** 待ちが 3 人以上のときだけ
- **あふれたら `+12 MORE JOINED` と数だけ添えます。** 行列を作りません
- **中央の告知 (ラウンド結果など) が出ている間は下へ逃げます**

名前が出なかった人も、**円は必ず出ます**（大砲が撃ちます）。
落ちるのは表示だけです。2 回目以降の入室では出しません
（出入りするだけで何度も名前が出てしまうため）。

止めたいときは `js/config.js` の `ui.join.banner.enabled` を `false` に。

### 円は大きめにしてあります

混んでくるとフィールドが広がり、画面はズームアウトします。そのぶん円は
小さく映るので、**顔と数字が読めること**を、画面に何個入るかより優先して
半径を 1.5 倍（20 → 30、上限は 48 → 72）にしました。

大きくするだけでは足りません。広げるかどうかは**面積**で見ているので、
1.5 倍にすると同じ人数でも占有率が 2.25 倍になり、そのぶん早く広がって
**画面上の大きさは元に戻ってしまいます**（実測で 1.09 倍にしかなりませんでした）。
`field.expand.growAt` も 0.3 → 0.52 に上げて、人数に対する広がり方が
前と同じになるようにしてあります。

結果、画面上の半径は視聴者 20 / 60 / 100 人のいずれでも約 1.5 倍になりました。

### 武器が育つ

**ギフトで攻撃力が上がると、その円の武器が変わります。** 武器は円のまわりを
**回りながら、当たった敵を斬ります**。円が触れていなくても、刃が届けば当たります。

| 攻撃力 | 武器 | 見た目 | 特殊能力 |
| --- | --- | --- | --- |
| 0 | – | 武器なし | – |
| 100 | NEON BLADE | 小さい光る剣 | – |
| 170 | TWIN BLADES | 光る剣が 2 本 | **TWIN STRIKE** 一振りで 2 体 |
| 250 | ENERGY SPEAR | 長いエネルギー槍 | **PIERCE** 2 体 + いちばん遠くまで届く |
| 330 | PLASMA AXE | 大型の斧 | **CLEAVE** 一振りで 3 体 |
| 410 | ENERGY SCYTHE | 大型の鎌が周囲を回る | **LIFESTEAL** 斬ったぶん HP が戻る |
| 500 | TWIN CHAKRAMS | 2 つの円刃が旋回 | **WHIRL** 4 体 + 回転が最速 |
| 590 | PLASMA CANNON | 円の横に大型砲 | **BARRAGE** 攻撃間隔が約半分 |
| 680 | ENERGY WINGS | 剣 + 背後のエネルギー翼 | **AEGIS** 受けるダメージ 0.6 倍 |
| 780 | ORBITAL WEAPON | 5 つのオーブが周回 | **ORBIT STRIKE** 5 方向から同時に |
| 880 | LEGENDARY CORE | コアの欠片と輪。最終形態 | **NOVA** 2.4 秒ごとに周囲へ大ダメージ |

攻撃力は base 40 から始まり、ギフトのコイン 1 につき +6 です
（10 コインで最初の剣、150 コインで最終形態）。

段が変わると**形・届く距離・腕の数・能力**が変わり、段の中でも
**大きさ・光り方・軌跡**が少しずつ育ちます。大きさは攻撃力に対して
まっすぐ増えるので、段の終わりの武器が次の段の頭より大きく見える、
といった逆転は起きません。

**いいねしか押さない人に武器は付きません。** そのぶん HP とスパイクで
戦えるようにしてあります（→ [2. 視聴者から見たルール](#2-視聴者から見たルール)）。

**見えている刃と当たる場所は必ず一致します。** 回転の角度は円が 1 つだけ持ち
(`circle.weaponAngle`)、画面はそれを読んで描くだけなので、
「当たったように見えたのに当たらない」が起きません。

円そのものの HP・攻撃力・速さ・大きさは、貯めたポイントが決めます。
武器が足すのは**武器のぶんの攻撃と特殊能力**だけです。

100 人が同時に操作した状態では、与ダメージの内訳は
本体 70% / 武器 30% ほど。撃破ペースは毎秒 8 体前後で、
武器を入れる前（毎秒 10 体）から大きくは動きません
（撃破の速さは敵の湧く間隔で頭打ちになるためです）。

節目の 2 つの段に届いたときだけ、画面中央に短い知らせが出ます。

```
   ENERGY SCYTHE              LEGENDARY CORE
     LIFESTEAL                     NOVA
```

**この間もゲームは止まりません。** 止めてしまうと、その数秒間 TikTok の
画面では何も起きていないように見えるためです。

武器は円の**外側**にだけ描き、円より先に描きます。だから、どれだけ育っても
**プロフィール画像が武器で隠れることはありません**。

斬ったときの見え方も武器ごとに変わります（剣は斬撃、槍は突進、
砲はエネルギー弾、といった具合です）。刃が敵に当たった位置に出るので、
どこに当たったのかが見て分かります。ただし画面が線で埋まらないよう、
同時に出るのは 40 個まで、1 つ 0.22 秒で消えます。

### 連続撃破（コンボ）

短い間に続けて倒すと、**とどめを刺した人の**スコアに倍率が掛かります。
3 連続から画面に `COMBO x3` と出ます。

- 4 秒以内に次を倒すと伸び、途切れると 1 に戻ります
- 倍率は 1 段 +10%、**最大でも 2 倍まで**。コンボ 1 回で順位がひっくり返ると、
  こつこつ育てた人の積み上げが軽くなるためです
- 数えるのは人ごとです。他人が倒しても伸びません

### ラウンド制（時間が来たら全部リセット）

**決まった時間で 1 本が終わり、全部リセットしてまた始まります。** 画面の
左上に残り時間が出て、0 になると結果（`WINNER @名前`）を出してから、円も
ランキングも消えて次のラウンドが始まります。

```
TIME 7:42  →  … →  TIME 0:00  →  WINNER @sakura (6 秒)  →  NEW ROUND
```

以前は `WAVE 1 → 2 → 3 …` と数を積み上げていました。数が積み上がるほど、
あとから来た人には「もう 7 まで進んでいる、今さら入っても」に見えます。
**どこから見ても次のラウンドは最初から**なので、遅れが生まれません。

長さは操作画面の **ROUND TIME**（1〜30 分、既定 10 分）で変えられます。
`js/config.js` の `director.roundMs` を `0` にすると、終わらない 1 本勝負に
なります（残り時間の表示も消えます）。

**結果を出している間もゲームは止まりません。** 止めると、その数秒だけ
TikTok の画面では何も起きていないように見えます。

### 特殊イベント

ラウンドとは別の時計で、90 秒ごとに約半分の確率で**特殊イベント**が起きます

### 背景を差し替える

**1080×1920 の画像を敷けます。** 操作画面の **BACKGROUND** から選ぶだけです
(選んだ画像はブラウザの中だけで使い、どこにも送りません)。

画像の座標と盤面の座標はそのまま一致します。画像の左上が (0, 0)、
右下が (1080, 1920) です。円が画像のどこを通るかを見ながら絵を作れます。

- **DIM** は画像に重ねる暗幕です。明るい絵だと円と敵が埋もれるので、
  そのときだけ濃くしてください (既定 28%)
- OBS のブラウザソースからは `game.html?bg=<画像のURL>&dim=0.3`
- 読み込めなかったときは既定の下地に戻るだけで、ゲームは止まりません

### 画面いっぱいにする仕組み

盤面の座標も**画面と同じ比**に合わせます。ゲーム画面が自分の縦横比を
engine に渡し、engine は幅 (1080) を保ったまま高さだけ変えます。

| 画面 | 盤面の座標 |
| --- | --- |
| 1080×1920 | 1080×1920 |
| 390×844 | 1080×2337 |

合わせないと画面の上下か左右に隙間ができて、「画面一面がスタジアム」に
なりません。操作画面のプレビューは比を変えません (小さい窓の比に盤面が
引きずられると、配信の見え方と違ってしまうためです)。

### ランキング

**左に TOP 5**。盤面が透けて見える濃さにしてあります。濃くすると読みやすい
代わりに、その下で戦っている円が見えなくなるためです。人数は
`js/config.js` の `ranking.size` で変えられます。

320×568 / 375×667 / 390×844 / 412×915 / 430×932 / 1080×1920 で確認済みです。
どのサイズでも横スクロールも縦スクロールも出ず、TOP 5 は 5 行ともアイコン付きで
出て、文字は切れません。横向きにすると `PORTRAIT MODE REQUIRED` になります。

高さは `100dvh` (スマホのアドレスバーで下が切れないように)、ふちは
`env(safe-area-inset-*)` に加えて右下を少し多めに空けています
(TikTok のボタン列やコメント欄と重なるため)。見る専用なので、タップしても何も起きません。

### 何が起きたか分かるようにしているもの

| 出るもの | いつ |
| --- | --- |
| 円の下に `@名前` | 円が生まれてから 4 秒 |
| 金色の輪 + `JOINED` + `WELCOME` | **入室で生まれた円**。7 秒間だけ光ります |
| `+42` がその場に飛ぶ | 敵を倒した |
| `+128  COMBO x5` | 3 連続以上で倒した |
| `BOSS DEFEATED` | 大物を倒した |
| `+HP` / `+ATK` / `+DRAIN` / `+SPIKE` | その力が増えた |
| `KO @名前` | 他の人の円を倒した |
| `NEW RANK #3` / `RANK UP #2` | ランクイン / TOP3 内で上がった |
| `@名前 #23 – 40 TO TOP5` | 直近に動いた人が TOP5 の外にいる |
| `BOSS ▓▓▓░` | HP 1000 以上の敵が居る間だけ |
| `WINNER @name` / `BOSS APPEARED` | ラウンドが終わった / 特殊イベント |

**どれも盤面を止めません。** 止めるとその間ゲームが見られないためです。
文字は出しっぱなしにせず、LIVE EVENT は 3 行・9 秒で消えます。

## 4. 円の動きとアイコン

### 動き

円も敵も**等速直線運動**で、**ぶつかると跳ね返ります**（ビリヤードと同じ）。

- 生まれたときの向きと速さのまま進み、**壁で反射**します
- 向きを変えるのは、壁か他の円にぶつかったときだけ。追いかけたり、ふらついたりしません
- **大きい円ほど押し勝ちます**（質量は半径から決まるので、ボスは小さい円に当たっても揺るぎません）
- 跳ね返ったあとも**速さは変わりません**。当たりどころで円が止まってしまわないようにしてあります

### 端に溜まらないための仕掛け

壁の反射は速度の x と y の大きさを変えません。つまり**壁とほぼ平行な向きで生まれた円は、
一生その壁沿いを往復します**。放っておくと端と角ばかりが混み合うので、3 つ対策しています
（`js/config.js` の `motion`）。

| 仕掛け | 何をしているか |
| --- | --- |
| 中央へ向けて出す | 生まれた瞬間の向きを中央寄りにします（`aimAtCenter`） |
| 壁と平行な向きを避ける | 縦・横にまっすぐな向きにはしません（`minWallAngleDeg`） |
| 壁際に居座ったら向け直す | 4 秒以上ずっと壁際にいた円だけ中央へ向け直します（`recenterAfterMs`） |

敵が湧く位置も壁の上ではなく少し内側です（`enemies.spawn.edgeInset`）。敵は倒されるまでが
短いので、湧いた場所がそのまま画面の印象になるためです。

押し離しは**重さで分け、壁に阻まれたぶんは相手へ回します**。これをしないと、角で
「押しても壁に戻される」状態になり、ボスの中に雑魚が埋まったまま止まって見えます。

2 分回したときの敵の居場所（面積比＝理想値）:

| | 修正前 | 修正後 | 面積比 |
| --- | --- | --- | --- |
| 四隅 | 28.7% | **13.3%** | 16% |
| 中央 3 分の 1 | 2.0% | **9.5%** | 11% |
| 重なりの最大 | 13.5 | **0** | 0 |

盤面が読めるので「あの円があの敵に当たりそう」が見て分かります。
動きを変えたいときは `js/config.js` で:

```js
collision: { bounce: false }                // 跳ね返らず、押し離すだけ
collision: { restitution: 0.6 }             // 跳ね返りを弱く
collision: { massFromRadius: false }         // 大きさに関係なく同じ重さ
enemies: { movement: { mode: 'wander' } }   // ふらふら + 視聴者円に寄る
viewers: { movement: { mode: 'seek' } }     // 最寄りの敵を追いかける
```

跳ね返るということは、**1 回の接触で殴れるのは 1 発だけ**ということです
（張り付いて削り続けられません）。そのぶん円は 1 発が重く、打たれ強くしてあります
（`viewers.base` の `hp` と `attack`）。ここを跳ね返る前の値に戻すと、
当たっても敵を倒せず自分だけ減っていきます。

当たり判定はフィールドを格子に切って隣の升だけを見るので、
円が 400 個あっても 1 フレーム 0.1ms 程度で、増えても重くなりません。

### アイコン

TikTok から取れたプロフィール画像を、そのまま円の中に描きます。

- 画像は**ユーザーごとに 1 回だけ**取得してキャッシュします（毎フレーム取りにいきません）
- 取れなかった / 読み込みに失敗した場合は、頭文字と色のアイコンになります
- ランキングの行にも同じ画像と、その人が貯めた力の合計 (`P42`) が出ます
- 円の中に力の合計が出ます（1000 以上は `1.2k`）
- アイコンが見える大きさになるよう、視聴者円は直径 40px 以上（1080 幅換算）にしてあります。
  ギフトが大きいほど円も大きくなります（`viewers.base.radius` と `scaling.maxRadius`）

画像が出ない場合は **tikhub 側が新しいか**を確認してください
（プロフィール画像を送るようになったのはこのブランチからです）。

## 5. アイテム

ときどきフィールドにアイテムが落ちます。**拾えるのは視聴者の円だけ**で、
敵は触れても素通りします（敵が強くなると視聴者の不利益になるため）。

| アイテム | 効果 |
| --- | --- |
| **POWER** | **100 コインのギフトと同じ攻撃力ポイント**を足して、HP 全快 |
| **HEAL** | **HP 全快**。暴れている最中なら**残り時間が 8 秒延びる**（残り 30 秒まで） |
| **SPEED** | 速くなる（何度拾っても、その円の元の速さの 2.4 倍まで） |

- **拾って弱くなることはありません。** エンジンは「今の値より大きいほう」しか採らないので、
  ポイントも HP も攻撃力も大きさも速さも下がりません。すでに上限の円が POWER を
  拾った場合も、下がらず HP が全快します。
- POWER のポイントはギフトと**同じ換算式**（`viewers.gain`）を通します。ギフトの設定を変えれば
  アイテムも一緒に変わるので、片方だけずれることはありません。
- 14 秒ごとに 1 つ、同時に 3 つまで。30 秒で消えます（消える前は点滅します）。
- **運の要素です。** 暴れている円がたまたま HEAL を拾えれば長く生き残れますが、
  拾えなくても損はしません（拾わなかった人が弱くなることはありません）。
- 拾われないまま消えても、誰も損をしません。

種類は `js/config.js` の `items.types` に 1 行足すだけで増やせます。

```js
{ id: 'mega', label: 'MEGA', color: '#a855f7', weight: 1,
  effect: { type: 'level', giftCoins: 500 } }
```

実行中に足すこともできます。

```js
CB.engine.addItemType({ id: 'event', label: 'EVENT', color: '#fff', weight: 0,
                        effect: { type: 'speed', multiplier: 2, maxMultiplier: 3 } });
CB.engine.spawnItem('event');     // その場に 1 つ置く
```

## 6. 100 人規模での実測

100 人が同時に操作している状態を**中継サーバー経由**で流したときの結果です
（1080x1920 / Chromium）。2 つの負荷で測っています。

### 操作画面とゲーム画面を両方開いた状態（100 人が操作、20 秒）

| | 操作画面 (1200×900) | ゲーム画面 (540×960) |
| --- | --- | --- |
| FPS | 40.9 | 40.9 |
| 最悪フレーム | 50ms | 48ms |

players=100 / circles=106 / enemies=32 / 撃破 332、受信 1,336 件すべて反映、エラー 0。
ゲーム画面 1 つだけ (1080×1920) なら 54fps です。
画面いっぱいのスタジアムにしたぶん、毎フレーム塗る面積がおおよそ 2 倍に
なっています (正方形の盤面を画面の一部に置いていたときは 60fps でした)。

**画面が 2 つでも物理計算は 1 回ぶんです。** `app.update()` は直前に進めたばかりなら
何もしないので、両方の画面が毎フレーム呼んでも二重には進みません。
どちらが進めるかを決め打ちにしていないのは、決めた側のウィンドウを最小化すると
`requestAnimationFrame` が止まってゲームごと止まってしまうためです。

### 実際の配信に近い負荷（100 人中 20 人が連打、5 分）

| | 結果 |
| --- | --- |
| 撃破ペース | 毎秒 14 体前後 |
| 円 | 43 個（1 人 1 つ） |
| 敵 | 17 体（HP 倍率 ×2.6） |
| FPS | 60 |

**1 人 1 つ**なので、画面に円が溜まり続けることはありません
（1 人が何個も持てた頃は、同じ負荷で 5 分後に 245 個まで増えていました）。

### 全員が全力で連打（毎秒 875 いいね = 実際の 10〜40 倍、3 分）

| | 結果 |
| --- | --- |
| イベント取りこぼし | **0 件**（9467 件すべて反映） |
| プロフィール画像 | 100 人ぶんを**各 1 回だけ**取得（以降はキャッシュ） |
| メモリ | 3〜9MB で安定（増え続けることはなし） |
| エンジンの 1 フレーム | 中央値 0.55ms / 16.7ms 超え **0 回** |
| 円 | 40〜60 個で安定（1 人 1 つのため） |
| FPS | 60 |
| エラー | なし |

円が 200 個を超えるほど溜まると、育った円は面積が約 6 倍あるため
塗る量が増えて FPS が落ちます（JavaScript 側は 1 フレーム 2.5ms 程度で、
残りはブラウザの描画。測定に使った headless Chromium は GPU を使わない
ソフトウェア描画なので、OBS や通常のブラウザではここまで落ちません）。
今は 1 人 1 つの制限でその状態にならないようにしています。

それでも混みすぎるときは `viewers.limits.maxPerUser`（既定 5）か
`viewers.levels.maxDurationMs`（既定 20 秒）を下げてください。
上限を超えたぶんは消えずに順番待ちになるので、下げても送ったぶんが無駄にはなりません。

### この規模で分かって直したこと

- **描画**: プロフィール画像は読み込み時に 1 回だけ丸く切り抜きます（毎フレームの
  切り抜きをやめて 2.9ms → 1.1ms）。力のバッジも数字ごとに 1 枚だけ作って
  貼り回します（0.9ms → 0.33ms）。バッジは**円の中**に描きます（外に出すと、
  円が密集したとき画面が数字で埋まります）。
- **ランキング**: 1 位の入れ替わり判定を、記録が変わるたび（毎秒 500 回）から
  1 フレーム 1 回へ（535ms → 7ms）。
- **当たり判定**: 升目を毎フレーム作り直さず使い回します（最悪フレーム 42ms → 3.8ms）。
- **敵の押し合い**: 視聴者の円は敵を押しません（`collision.enemiesArePushed`）。
- **敵の硬さ**: 場の合計ポイントに応じて敵の HP を上げます（`enemies.scale`）。
  これが無いと、育った円が湧いた瞬間の敵を溶かしてしまい、毎秒 200 体以上が
  撃破されて画面から敵が消えます。

## 7. 止まらない画面

**このゲームの最重要仕様です。** TikTok のイベントが 1 件も来なくても、画面は動き続けます。

- 敵は一定間隔で自動生成され、常にフィールド内を動きます
- 敵が下限を割ったら、間隔を待たずに補充します
- 敵同士・円同士は重なったままにならないよう押し離します
- 誰も反応していない間は**デモ視聴者**が円を出し、戦闘が続きます

本物の視聴者のイベント（LIKE など）が 1 件でも届いたら、デモは止まります。
このとき円は**1 つずつ**引き上げます（`demo.retireIntervalMs`）。一斉に消すと、
最初の LIKE の瞬間に画面の円が全部消えて**リセットされたように見える**ためです。
ランキングの記録はその場で消え、引き上げ中の円が敵を倒しても点は入りません。

`test/idle-loop.test.js` が、イベント 0 件のまま 60 秒回して
「敵が出続ける / 戦闘が起きる / 敵が倒れる / ランキングが動く」を確認しています。

## 8. 効果音

音源ファイルは要りません。**WebAudio でその場で合成**しているので、
`file://` で開いても、素材を配らなくても鳴ります。

| いつ | 音 |
| --- | --- |
| 敵に当たった | 短い打撃音 (いちばんよく鳴るので小さめ) |
| 敵を倒した | 「ドーン」。**敵が大きいほど低い音**になります |
| 視聴者の円が力尽きた | 低い短音 |
| LIKE で円が出た | 小さな上がり音 |
| FOLLOW / SHARE | 2 音 |
| GIFT | 3 音の上がり |
| アイテムを拾った | 3 音の上がり |
| ランキング 1 位が入れ替わった | ベル |

- 撃破もダメージも 1 秒に何十回も起きるので、**音ごとの最短間隔**と
  **1 秒あたりの上限**で間引いています (`config.audio`)。潰れて聞こえなくなりません。
- 敵ごとの音の高さは `enemies.types[].killPitch` です。敵を足すときに一緒に決められます。
- ブラウザは操作前の自動再生を止めます。止められている間は画面に
  「🔇 クリックで音が出ます」と出て、**最初のクリックで鳴り始めます**
  (ゲームの進行は止まりません)。OBS のブラウザソースはそのまま鳴ります。
- テストパネルの `SOUND ON` / `VOL` で切り替えと音量調整ができます。
  配信中にコンソールからでも変えられます。

```js
CB.sfx.toggle();        // 入 / 切
CB.sfx.setVolume(0.2);  // 音量
```

音量の初期値は `config.audio.volume` (既定 0.35)。BGM を流すなら下げてください。

## 9. 設定

調整値はすべて [`js/config.js`](js/config.js) にあります。ゲームのコードに数値はありません。

### 9.1 敵の種類を足す

`enemies.types` に 1 行足すだけです。ゲーム側は id を見ないので、それだけで出てきます。

```js
{ id: 'megaboss', label: 'MEGA', hp: 20000, radius: 90, speed: 18,
  attack: 120, attackIntervalMs: 600, points: 500, weight: 1, color: '#a855f7' }
```

実行中に足すこともできます (イベントボスなどを想定):

```js
CB.engine.addEnemyType({ id: 'event-boss', /* ... */ });
CB.engine.spawnEnemy('event-boss');
```

| 種類 | HP | 撃破ポイント |
| --- | --- | --- |
| NORMAL | 100 | +1 |
| STRONG | 300 | +5 |
| ELITE | 1000 | +20 |
| BOSS | 5000 | +100 |

### 9.2 ステータス

何をするとどの力が付くかは `viewers.gain` と `viewers.stats` に全部あります。

```js
gain: {
  likesPerPoint: 10,      // 10 いいねで HP 1 ポイント
  attackPerCoin: 1,       // コイン 1 で攻撃力 1 ポイント
  sharePoints: 1,         // シェアでドレイン 1 ポイント
  followPoints: 3,        // フォローでスパイク 3 ポイント
  followOncePerUser: true,
  joinPoints: { hp: 3, spike: 1 },
  joinOncePerUser: true
},

stats: {
  hp:     { per: 70,   max: 9000 },   // 1 ポイントで HP +70 (上限 +9000)
  attack: { per: 6,    max: 900  },
  drain:  { per: 0.05, max: 0.5  },
  spike:  { per: 1,    max: 12   }
}
```

**ポイントは人が持ちます**（円ではありません）。倒されて円が消えても残るので、
次の行動で同じ強さのまま戻ってきます。

円の HP・攻撃力・大きさは、貯めたポイントだけから決まります
（`viewers.base` と `viewers.size`）。

```
HP     = 400 + HP ポイント × 70
攻撃力 = 40  + 攻撃ポイント × 6
半径   = 30 × (1 + 合計ポイント) ^ 0.13   (上限 72)
速さ   = 165 (全員同じ)
```

### 9.2.1 スパイクと PvP

```js
spikes: {
  damageBase: 6,          // 棘の基礎ダメージ
  hpPerDamage: 90,        // 最大 HP がこれだけ増えるごとに +1
  countScale: { base: 0.5, per: 0.25, max: 3 },   // 本数による倍率
  intervalMs: 400,        // 相手ごとに数える間隔
  reach: 0.34             // 円の外へ出る長さ (半径の倍率)
},

pvp: {
  enabled: true,
  damageRatio: 0.3,       // 相手の円に対する攻撃力の倍率
  intervalMs: 450,
  pointsPerVictimPoint: 1.2,   // 倒したときの点 = 相手の合計ポイント × これ
  minPoints: 5
}
```

`pvp.enabled: false` にすると、円どうしは押し合うだけで削り合いません
（敵だけを狩る形に戻ります）。

### 9.3 撃破ポイントの配り方

```js
scoring: {
  mode: 'lastHit',        // 'lastHit' | 'damage'
  killCredit: 'lastHit',  // 'lastHit' | 'topDamage'
  pointsPerDamage: 0
}
```

- `lastHit` … とどめを刺した人が全ポイントを取る (初期設定)
- `damage` … 与えたダメージの割合でポイントを分ける

どちらでも動くように、敵は**常に「誰がどれだけ削ったか」を記録**しています。
KILL 数だけは 1 人にしか付きません (割ると整数でなくなるため)。

### 9.4 ランキングの基準

```js
ranking: { sortBy: 'score', order: 'desc', size: 10 }
```

`score` / `kills` / `damage` のどれでも並べられます。実行中にも変えられます。

```js
CB.leaderboard.setSort('kills');
```

## 10. 作り

```
TikTok Event  ->  Game Event  ->  Battle Entity  ->  Enemy  ->  Battle  ->  Leaderboard
```

| --- | --- | --- |

| `js/event-router.js` | TikTok の語彙をゲームイベントへ翻訳する | **はい (ここが最後)** |
| `js/game-session.js` | イベント -> 円の生成 / ポイントの配分 | いいえ |
| `js/game.js` | 敵とアイテムの生成・移動・衝突・戦闘 (バトルエンジン) | いいえ |
| `js/leaderboard.js` | ユーザーごとの成績とランキング | いいえ |

| `js/avatars.js` | プロフィール画像のキャッシュ | いいえ |
| `js/audio.js` | 効果音 (WebAudio で合成) | いいえ |
| `js/director.js` | ラウンドの時計と特殊イベント | いいえ |
| `js/cannon.js` | 円を撃ち出す大砲 (順番待ちと段階だけ。描かない) | いいえ |

| `js/renderer.js` | 画面 (canvas + DOM) | いいえ |

| `js/game-view.js` | 描画・音・演出の配線 (状態を読むだけ) | いいえ |
| `js/control.js` | 操作画面の設定 UI | いいえ |
| `js/config.js` | すべての調整値 | いいえ |

**ゲーム側は TikTok Connector を直接操作しません。**
`game.js` / `game-session.js` / `leaderboard.js` に `giftId` も `uniqueId` も出てきません。
別の配信サービスを足すときは、アダプタとルーターをもう 1 組書くだけで済みます。

複数 LIVE を同時に受けるときは、LIVE ごとに engine + session を作って
`router.attach(liveId, session)` します。

将来足せるように分けてあるもの: 敵の種類 / ボス / イベントボス / ランキング報酬 /
装備 / 特殊攻撃 / ギフト専用攻撃 / 複数 LIVE 接続。

### 10.1 視聴者の円が持つ情報

```js
{ id, ownerId, ownerName, displayName, profileImageUrl, sourceEvent,
  points: { hp, attack, drain, spike }, power,
  hp, maxHp, attack, drain, spikes, spikeDamage, radius, speed,
  position: { x, y }, velocity: { x, y }, kills, damage, bornAt }
```

### 10.2 ランキングが持つ情報

```js
{ userId, userName, profileImageUrl, kills, damage, score,
  power, maxPower, queued, lastActivity }
```

`power` は貯めた力の合計、`maxPower` はこれまでに届いた一番上の合計です
（貯めた実績は、円が倒れても消えません）。

## 12. 繋がらないとき

画面右上が「中継サーバー未接続」のままのときは、括弧の中に**どこを見にいっているか**が出ます。

| 状態 | 意味 |
| --- | --- |
| `LIVE @名前` | 配信に繋がっている（正常） |
| `中継サーバーに接続済み` | tikhub には繋がったが、まだ配信を指定していない |
| `配信の開始を待っています` | 指定した人がまだ配信していない |
| `中継サーバー未接続 (127.0.0.1:8787)` | tikhub が動いていない / 別のポートで動いている |

順に確認してください。

1. **tikhub が動いているか。** `http://127.0.0.1:8787/health` をブラウザで開いて
   `{"ok":true...}` が出れば動いています。
2. **ポートが違わないか。** 8787 が埋まっていると tikhub は `--serve=8788` などで
   起動されている場合があります。そのときは `?bridge=http://127.0.0.1:8788/events` を
   URL の後ろに付けてください。
3. **別の PC の tikhub に繋ぐ場合。** `?bridge=http://その PC の IP:8787/events` を付け、
   tikhub 側は `BRIDGE_HOST=0.0.0.0` で起動します。

ゲームは **tikhub 以外の場所から開いても繋がります**。VS Code の Live Server、
社内サーバー、`index.html` の直接オープン（`file://`）のいずれでも、
同じ PC の `127.0.0.1:8787` を自動で探しにいきます。
`?bridge=` を付けたときだけ、そこだけを見ます。

> https のサイトに置いた場合、Safari は `http://127.0.0.1` への接続を止めます。
> Chrome / Edge / Firefox は繋がります。

## 13. コンソールから試す

```js
// 本番と同じ経路で 1 件流し込む
CB.tiktok.handleEvent({ type: 'like',   user: { uniqueId: 'taro' }, count: 100 });
CB.tiktok.handleEvent({ type: 'follow', user: { uniqueId: 'taro' } });
CB.tiktok.handleEvent({ type: 'share',  user: { uniqueId: 'taro' } });
CB.tiktok.handleEvent({ type: 'gift',   user: { uniqueId: 'taro' }, diamondCount: 100 });
CB.tiktok.handleEvent({ type: 'member', user: { uniqueId: 'taro' } });   // 入室

CB.engine.spawnEnemy('boss');      // 敵を出す
CB.engine.spawnItem('power');      // アイテムを置く
CB.director.trigger('swarm');      // 特殊イベントを起こす (boss / swarm / rare / elite)
CB.renderer.weapons.tierFor(340);  // その攻撃力の武器と能力を調べる
CB.renderer.debugHits = true;      // 武器の当たり判定を線で出す (確認用)
CB.app.applySettings({ backgroundUrl: 'stadium.png' });   // 背景を差し替える
CB.leaderboard.setSort('kills');   // ランキングの基準を変える
CB.app.applySettings({ sfxVolume: 0.5 });   // 音量 (ゲーム画面にも即座に届く)
CB.reset();                        // 全部やり直す
```

操作画面では `CB.app` がゲームの本体です。ゲーム画面で開いたコンソールからは
`CB.view.app` で同じものに触れます (`window.opener.CB.app` と同じオブジェクトです)。
