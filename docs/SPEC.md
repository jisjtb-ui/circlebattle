# CIRCLE BATTLE 仕様書

TikTok LIVE 連動バトルゲーム。最終更新: 2026-09-07

---

## 1. 概要

### 1.1 ゲームの構造

```
        【自動生成される敵】
                VS
        【TikTok LIVE 視聴者】
```

視聴者が TikTok LIVE 上で **LIKE / FOLLOW / SHARE / GIFT / 入室** を行うと、
その視聴者専用の円が生まれ、以後の行動でレベルが上がっていく。
円は自動生成される敵を攻撃し、撃破数とスコアでリアルタイムランキングを競う。

### 1.2 設計方針

| 方針 | 内容 |
| --- | --- |
| チーム概念を持たない | `Team A` / `Team B` のような固定の陣営は実装しない。ランキングは常に個人単位 |
| 画面が止まらない | TikTok イベントが 0 件でも、敵の生成・移動・衝突・撃破のループは回り続ける |
| 視聴者に不利益を出さない | アイテムも敵の強化も、既存の視聴者が弱くなる方向には働かない |
| TikTok を game 層に持ち込まない | TikTok 固有の語彙は Event Router までで止める |
| 数値はすべて設定に出す | ゲームロジックに数値を直書きしない。調整は `js/config.js` の 1 ファイルで完結する |

### 1.3 想定環境

| 項目 | 内容 |
| --- | --- |
| 実行環境 | ブラウザ（Chromium 系推奨）。`file://` でも動作 |
| 配信 | OBS ブラウザソース 1080×1920（縦） |
| 依存 | なし（外部ライブラリ・ビルド不要）。中継サーバーのみ Node.js 20.12+ |
| 音源・画像 | ファイル不要（効果音は WebAudio 合成、アイコンは TikTok から取得） |

## 2. システム構成

### 2.1 リポジトリ

| リポジトリ | 役割 |
| --- | --- |
| `circlebattle` | ゲーム本体（ブラウザで動く） |
| `tikhub` | TikTok LIVE への接続、イベント正規化、SSE 中継、ゲーム配信 |
| `kawaiivsbeautiful` | 既存の別ゲーム。本ゲームとは独立（接続部分の実装を流用） |

### 2.2 データの流れ

```
TikTok LIVE
    │  (tiktok-live-connector / 非公式)
    ▼
tikhub  src/sources/tiktok.js     受信
        src/events.js             正規化（profileImageUrl の抽出を含む）
        src/bridge.js             SSE 配信 + ゲーム本体の配信
    │  Server-Sent Events  http://127.0.0.1:8787/events
    ▼
circlebattle
    js/tiktok-adapter.js   受信口（SSE / WebSocket）
    js/event-router.js     TikTok の語彙 → ゲームイベント     ★ここが境界
    js/game-session.js     ゲームイベント → レベル・円・得点配分
    js/game.js             敵・円・アイテム・物理・戦闘
    js/director.js         ウェーブと特殊イベント（敵だけを動かす）
    js/leaderboard.js      ユーザー成績とランキング
    js/app.js              上を 1 つに束ねた「ゲームの状態」
    js/game-view.js        描画・音・演出（状態を読むだけ）
    js/renderer.js         描画（canvas + DOM）
```

### 2.2.1 ウィンドウ構成

操作画面（`index.html`）とゲーム画面（`game.html`）に分かれる。
**ゲームは 1 つだけ**で、ゲーム画面は別プロセスではない。

```
        操作画面 index.html
        ├ TikTok LIVE の接続        ┐
        ├ 音量 / BGM(MP3)           │ 触るものは全部こちら
        ├ ゲーム・敵・イベント設定    │
        ├ テストパネル               ┘
        └ CB.app  ← ゲームの状態はここに 1 つだけ
                 ▲
                 │ window.opener.CB.app（同じオブジェクトを読む）
                 │
        ゲーム画面 game.html
        ├ Game Status
        ├ Battle Field（正方形）
        ├ TOP 10 PLAYER
        └ LIVE EVENT（数行）
```

| | 操作画面 | ゲーム画面 |
| --- | --- | --- |
| 用途 | 配信者が触る | 配信に映す（OBS でキャプチャ） |
| 画面比 | PC 向け・可変 | 9:16（1080×1920 基準） |
| 音 | 鳴らさない | 効果音・BGM |
| ゲームの状態 | **持つ** | 操作画面のものを読む |
| 単独で開いた場合 | – | 自分で組み立てて動く（OBS のブラウザソース用） |

設定は `app.settings`（効果音・BGM）と `config`（ゲームの数値）で共有され、
操作画面で変えた瞬間にゲーム画面へ反映される。

時刻は **`Date.now()` に統一**している。`performance.now()` はウィンドウごとに
原点が違うため、2 つの画面から同じゲームを進めると時間が飛ぶ。
`app.update()` は直前に進めたばかりなら何もしないので、両方の画面が毎フレーム
呼んでも二重には進まない。どちらが進めるかを決め打ちにしないのは、
決めた側のウィンドウを最小化すると `requestAnimationFrame` が止まり、
ゲームごと止まってしまうため。

**Event Router から下流には TikTok 固有の情報が一切流れない。**
`game.js` / `game-session.js` / `leaderboard.js` に `giftId`・`diamondCount`・`uniqueId` は出現しない。

## 3. イベント仕様

### 3.1 受信する TikTok イベント

| TikTok | ゲームイベント | 備考 |
| --- | --- | --- |
| `like` | `LIKE` | `count` を使用（まとめて届く） |
| `follow` | `FOLLOW` | |
| `share` | `SHARE` | |
| `gift` | `GIFT` | 連打中（`finished === false`）は無視し、確定時のみ |
| `member` / `join` / `enter` | `JOIN` | 入室 |
| `chat` / `comment` | `COMMENT` | **ゲームには影響しない**（将来のコマンド用） |
| `viewer` ほか | – | 破棄 |

### 3.2 ユーザー情報の正規化

| フィールド | 取得元（優先順） |
| --- | --- |
| `id` | `user.id` → `uniqueId`（userId が取れない配信への対応） |
| `uniqueId` | `user.uniqueId` → `displayId` → `username` |
| `displayName` | `user.nickname` → `displayName` |
| `profileImageUrl` | `profileImageUrl` → `profilePictureUrl` → `avatarThumb.urlList[]` → `avatarMedium` → `avatarLarge` |

プロフィール画像は 100x100 の webp を優先。取得できない場合は `null`（画面側で頭文字アイコン）。

### 3.3 ギフトのコイン換算

```
優先順位:  gifts.byId[giftId]  →  gifts.byName[giftName]  →  diamondCount × coinsPerDiamond  →  defaultCoins
コイン価値 = 単価 × repeatCount
```

| 設定 | 既定値 |
| --- | --- |
| `gifts.coinsPerDiamond` | 1 |
| `gifts.defaultCoins` | 1 |
| `gifts.byId` / `byName` | 空（個別指定用） |

## 4. レベル仕様

### 4.1 レベルの上がり方

**円は増えるのではなく育つ。** 1 人が育てている円は 1 つで、行動するとその円のレベルが上がる。

| 操作 | 上がるレベル | 設定 |
| --- | --- | --- |
| いいね 10 回 | +1 | `levels.likesPerLevel: 10` |
| フォロー | +10 | `levels.follow: 10` |
| シェア | +5 | `levels.share: 5` |
| ギフト | コイン 1 につき +1（最低 +1） | `levels.giftLevelsPerCoin: 1` |
| 入室 | レベル 20 の円を生成（1 人 1 回のみ） | `levels.join: 20` / `joinOncePerUser: true` |

- レベル範囲は **1 〜 100**（`levels.max: 100`）
- いいねの端数は**ユーザーごとに**繰り越す（7 + 5 = 12 → 1 レベル、余り 2）
- 入室ボーナスは 1 人 1 回のみ。入り直しても再取得できない

### 4.2 円の能力値

```
値 = base × レベル ^ exp
```

| 値 | base（Lv1） | 指数 | 上限 |
| --- | --- | --- | --- |
| HP | 300 | 0.65 | – |
| 攻撃力 | 36 | 0.6 | – |
| 半径 | 20 | 0.19 | 48 |
| 速さ | 165 | 0.22 | 700 |
| 攻撃間隔 | 300ms | – | – |

| レベル | HP | 攻撃力 | 半径 | 速さ |
| --- | --- | --- | --- | --- |
| 1 | 300 | 36 | 20.0 | 165 |
| 10 | 1,340 | 143 | 31.0 | 274 |
| 20 | 2,103 | 217 | 35.3 | 319 |
| 50 | 3,815 | 376 | 42.1 | 390 |
| 80 | 5,178 | 499 | 46.0 | 433 |
| 100 | 5,986 | 571 | 48.0 | 454 |

レベルアップ時、増えた HP 分はそのまま回復する（育てて打たれ弱くならない）。

### 4.3 最大レベル（MAX 状態）

レベル 100 到達で **20 秒間の MAX 状態**に入る。

| 項目 | 内容 |
| --- | --- |
| 継続時間 | 20 秒（`levels.maxDurationMs`、0 で無期限） |
| 攻撃力 | ×2.5（`levels.maxBonus.attack`） |
| 速さ | ×1.8（上限 700） |
| HP | 突入時に全快 |
| 表示 | 虹色オーラ + 金色の `MAX` バッジ + 残り時間の白いリング |
| 終了時 | 燃え尽きて消滅（`circle:removed` reason `burnout`） |

MAX 状態の実効値: **攻撃力 1,428 / 速さ 700**

高額ギフトやアイテムで一気に 100 に達した場合も同様に MAX 状態へ入る。

### 4.4 MAX 後の再スタート

MAX の円が残っている状態で次の行動があった場合、**新しい円**が生まれる。
新しい円の初期レベルは**その行動ぶんのレベル**（`levels.restartAtActionLevel: true`）。

| 行動 | 新しい円の初期レベル |
| --- | --- |
| 10 いいね | 1 |
| フォロー | 10 |
| 50 コインのギフト | 50 |

円が敵に倒された場合も、次の行動で新しい円が生まれる。

### 4.5 保有数と順番待ち（キュー）

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `limits.maxPerUser` | 5 | 1 人がフィールドに置ける円の上限 |
| `limits.queue` | 5 | 順番待ちの列の長さ |
| `limits.maxCircles` | 400 | フィールド全体の上限（安全弁） |

```
フィールド [Lv100][Lv100][Lv100][Lv100][Lv100]   ← 5 個で満員
順番待ち                          [Lv30][Lv12]   ← 次に入る円
```

- 上限に達した状態で新しい円ができる場合、**押し出さずに列へ積む**
- 円が 1 つ減る（燃え尽き / 撃破）と、**列の先頭が自動で投入される**
- 列も満杯の場合、**列の最後の円のレベルに加算**する（送ったぶんは失われない）
- 全体上限に達した場合のみ、最古の円から押し出す（この場合は列から補充しない）
- 順番待ちの数はランキングに `Lv100 +2` の形で表示

## 5. 敵仕様

### 5.1 種類

| id | 表示 | HP | 半径 | 速さ | 攻撃力 | 撃破ポイント | 出現比 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `normal` | NORMAL | 100 | 20 | 58 | 6 | 1 | 62 |
| `strong` | STRONG | 300 | 28 | 48 | 12 | 5 | 24 |
| `elite` | ELITE | 1,000 | 40 | 38 | 26 | 20 | 11 |
| `boss` | BOSS | 5,000 | 66 | 26 | 60 | 100 | 3 |
| `rare` | RARE | 2,500 | 34 | 120 | 20 | 300 | 0 |

攻撃間隔は 600〜700ms。種類は `enemies.types` に 1 行足すだけで追加でき、
実行中も `engine.addEnemyType()` で追加できる。

`rare` は出現比 0。通常は湧かず、特殊イベント（§5.4）でだけ出る。
速く（120）小さく（34）逃げ回るので、倒せれば大きい（300）。

### 5.2 生成

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `spawn.intervalMs` | 1000 | 生成間隔 |
| `spawn.initialCount` | 8 | 起動時の配置数 |
| `spawn.minAlive` | 6 | 下限。割ったら間隔を待たずに補充 |
| `spawn.maxAlive` | 48 | 上限 |
| `spawn.circlesPerExtraEnemy` | 4 | 視聴者円 4 個ごとに下限 +1 |
| `spawn.edgeInset` | 0.13 | 壁からどれだけ内側に湧かせるか |

- 湧く位置は壁の上ではなく内側（壁沿いに張り付く敵を作らないため）
- 辺に沿う位置も端 10% を避ける（角に固まらないため）
- 他の敵と重なる位置しか無い場合は**生成を見送る**（次の間隔で再試行）

### 5.3 場の勢力に応じた強化

```
HP 倍率 = 1 + (フィールド上の視聴者円の合計レベル ÷ 900)   上限 15 倍
```

- 上げるのは **HP のみ**。撃破ポイントも敵の攻撃力も変えない
  （育っていない視聴者が不利にならないため）
- これが無い場合、育った円が湧いた瞬間の敵を溶かし、毎秒 200 体以上が撃破されて
  画面から敵が消える（100 人負荷で実測）

### 5.4 ウェーブと特殊イベント

`js/director.js`。**敵しか触らない。**視聴者の円もランキングも消さない。
区切りのたびに積み上げが消えると、育てる意味がなくなるため。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `director.waveMs` | 90,000 | ウェーブが進む間隔 |
| `director.eventChance` | 0.5 | ウェーブ更新時に特殊イベントが起きる確率 |

起きうるイベント（`director.events` の `weight` で抽選）:

| id | 表示 | 内容 | 比 |
| --- | --- | --- | --- |
| `boss` | BOSS APPEARED | BOSS ×2 | 3 |
| `swarm` | SWARM INCOMING | ランダムな敵 ×12 | 3 |
| `rare` | RARE ENEMY | RARE ×1 | 2 |
| `elite` | ELITE SQUAD | ELITE ×5 | 2 |

- 平均すると **3 分に 1 回**程度。毎回起きると「特殊」ではなくなる
- `director.trigger('boss')` で手動でも起こせる（テストパネルの SWARM ボタン）
- 出す文字は `label` / `sub`。ゲームの進行は止めない（バナーが 2.2 秒出るだけ）

## 6. アイテム仕様

一定間隔でフィールドに出現。**視聴者の円だけが拾える**（敵は素通り）。

| id | 表示 | 効果 | 出現比 |
| --- | --- | --- | --- |
| `power` | POWER | 100 コインギフト相当のレベル（＝最大レベル）まで引き上げ、HP 全快、MAX 状態へ突入 | 1 |
| `heal` | HEAL | HP 全快。MAX 状態中なら**残り時間 +8 秒**（残り 30 秒まで） | 1.4 |
| `speed` | SPEED | 速さ ×1.6（その円の元の速さの 2.4 倍まで） | 1 |

| 設定 | 既定値 |
| --- | --- |
| `spawn.intervalMs` | 14,000ms |
| `spawn.firstDelayMs` | 8,000ms |
| `spawn.maxAlive` | 3 |
| `lifetimeMs` | 30,000ms（消滅前に点滅） |
| `radius` | 30 |

### 6.1 不利益を出さない保証

アイテムの効果適用時、**どの値も「現在値と新値の大きいほう」しか採らない**。
レベル・HP・攻撃力・半径・速さのいずれも下がらない。
（例：レベルが上がると通常は速さが上がるが、仮に下がる設定でもアイテムでは下がらない）

テスト `拾って弱くなる値は 1 つも無い` が、全アイテム × Lv1/20/200 の円で検証している。

## 7. 物理仕様

### 7.1 移動

| 対象 | 既定 | 内容 |
| --- | --- | --- |
| 敵 | `linear` | 等速直線運動。壁で反射 |
| 視聴者円 | `linear` | 等速直線運動。壁で反射 |

`enemies.movement.mode: 'wander'` で徘徊＋追尾、`viewers.movement.mode: 'seek'` で
最寄りの敵を追尾する動きに戻せる。

### 7.2 衝突

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `collision.bounce` | true | ぶつかると反射（ビリヤード式） |
| `collision.restitution` | 1 | 反発係数 |
| `collision.massFromRadius` | true | 質量 = 半径²。大きい円ほど押し勝つ |
| `collision.keepSpeed` | true | 反射後も速さを維持（止まる円を作らない） |
| `collision.enemiesArePushed` | **false** | 視聴者円は敵を押さない（跳ね返るだけ） |
| `collision.separation` | 140 | 重なりを解消する速さ |
| `collision.separationRatio` | 0.3 | 深い重なりを 1 フレームで解消する割合 |

- 押し離す量は質量で分配し、壁に阻まれて動けなかったぶんは相手側へ回す
  （角で「押しても壁に戻される」状態を防ぐ）
- `enemiesArePushed: false` の理由：円が数百個になると四方から押された敵が
  重なって隅に固まるため（100 人負荷で重なり最大 54 を観測）

### 7.3 端に溜まらないための仕掛け

壁の反射は速度の x/y 成分の絶対値を保つため、**壁と平行な向きで生まれた円は
一生その壁沿いを往復する**。以下で対処する。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `motion.aimAtCenter` | 0.6 | 生成時、中央方向 ±72 度の範囲へ撃ち出す |
| `motion.minWallAngleDeg` | 20 | 軸に平行に近い向きを避ける |
| `motion.recenterAfterMs` | 4,000 | 壁際に居続けたら中央へ向け直す |
| `motion.wallBand` | 1.8 | 「壁際」と見なす距離（半径の倍数） |

実測（2 分間、面積比が理想値）:

| | 対策前 | 対策後 | 面積比 |
| --- | --- | --- | --- |
| 四隅にいた割合 | 28.7% | 13.3% | 16% |
| 中央 1/3 にいた割合 | 2.0% | 9.5% | 11% |
| 敵同士の重なり最大 | 13.5 | 0 | 0 |

### 7.4 フィールドの自動拡縮

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `field.width` / `height` | 1000 | 基準の広さ |
| `expand.growAt` | 0.30 | 占有率がこれを超えたら 1 段階拡大 |
| `expand.shrinkAt` | 0.12 | これを下回ったら 1 段階縮小 |
| `expand.step` | 1.35 | 1 段階の倍率（面積では約 1.8 倍） |
| `expand.maxSteps` | 3 | 最大 3 段階（×2.46） |
| `expand.durationMs` | 2,000 | 変化にかける時間 |
| `expand.cooldownMs` | 4,000 | 変化後、次の判定までの待ち |

- 判定は**占有率**（円と敵の面積の合計 ÷ 床面積）。数ではなく面積で見るのは、
  レベル 100 の円が Lv1 の約 6 倍の面積を持つため
- 変化中は ease-in-out で滑らかに補間し、**中の座標も同じ割合で拡縮**する
  （位置関係は変わらず、半径と速さは据え置き ＝ 密度だけが下がる）
- 画面には `STAGE EXPANDED` / `STAGE SHRINKING` を英語で表示（表示時間 = 変化時間）

### 7.5 フレーム制御

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `loop.maxDeltaMs` | 50 | 1 フレームで進める時間の上限 |

タブを裏に回して戻したときに、まとめて何秒も進んで円が壁を突き抜けるのを防ぐ。

## 8. 戦闘・得点仕様

### 8.1 戦闘

- 視聴者円と敵が接触したとき、双方が自分の攻撃間隔でダメージを与え合う
- 敵の HP が 0 で撃破。円の HP が 0 で消滅
- 敵は「誰がどれだけ削ったか」を常に記録する（`contributions`）

### 8.2 得点配分

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `scoring.mode` | `lastHit` | `lastHit` = とどめを刺した 1 人が全ポイント / `damage` = 与ダメージ比で分配 |
| `scoring.killCredit` | `lastHit` | `damage` モード時、KILL 数を誰に付けるか（`lastHit` / `topDamage`） |
| `scoring.pointsPerDamage` | 0 | ダメージ 1 につき入るスコア |
| `scoring.minShare` | 0.02 | `damage` モードで無視する貢献の下限 |

KILL 数は必ず 1 人にのみ加算する（分割すると整数でなくなるため）。

### 8.2.1 連続撃破（コンボ）

短い間に続けて倒すと、**とどめを刺した人の**ポイントに倍率が掛かる。

| 設定 | 既定値 | 内容 |
| --- | --- | --- |
| `combo.enabled` | true | – |
| `combo.windowMs` | 4,000 | この時間内の次の撃破で伸びる |
| `combo.showFrom` | 3 | 画面に `COMBO x3` と出し始める回数 |
| `combo.bonusPerHit` | 0.1 | 1 段あたりの倍率 |
| `combo.maxBonus` | 1.0 | 倍率の上限（**最大 2 倍**） |

- 数えるのは人ごと。他人の撃破では伸びない
- 上限を 2 倍で止めているのは、コンボ 1 回で順位がひっくり返ると、
  こつこつ育てた人の積み上げが軽くなるため
- 途切れると 1 に戻る

### 8.3 ランキング

ユーザーごとに保持するデータ:

```js
{ userId, userName, profileImageUrl, kills, damage, score,
  level, maxLevel, queued, lastActivity }
```

| 設定 | 既定値 |
| --- | --- |
| `ranking.sortBy` | `score`（`kills` / `damage` も選択可） |
| `ranking.order` | `desc` |
| `ranking.size` | 10 |

- 同点時は score → kills → damage → 先に到達した人の順
- 11 位以下は表示しない
- `maxLevel` は下がらない（新しい円になっても最大到達レベルは残る）
- 実行中に `CB.leaderboard.setSort('kills')` で基準を変更できる

## 9. 画面仕様

### 9.1 レイアウト（ゲーム画面 `game.html`）

TikTok LIVE の縦画面（**1080×1920 = 9:16**）を基準にする。

```
┌──────────────────────────┐
│ WAVE 3          ● LIVE   │  ウェーブ / 接続状態
│ ENEMIES DEFEATED         │
│ 2,951                    │  撃破総数
│ ENEMIES 48 CIRCLES 245   │  現在数
│ BOSS ▓▓▓▓▓▓░░░░  5,168   │  大物が居る間だけ
├──────────────────────────┤
│                          │
│    ○      ●      ○       │  正方形のバトルフィールド（主役）
│         ●     ○          │  ● 敵 / ○ 視聴者の円
│                          │
├──────────────────────────┤
│ TOP 10 PLAYER      SCORE │
│ 1 @PlayerA Lv100 +2  128 │  常時 10 行ぶんを確保
│ 2 @PlayerB Lv54       96 │
│ …                        │
│ @PlayerZ #23 – 40 TO TOP10│ 圏外の人の順位（直近に動いた人）
├──────────────────────────┤
│ @PlayerC LIKE → Lv7      │  LIVE EVENT（3 行・自動で消える）
│ @PlayerD NEW RANK #9     │
└──────────────────────────┘
```

視覚的な優先順位は **フィールド > ステータス > TOP10 > イベント**。
狭い画面で削るのは下から。フィールドは最後まで正方形のまま残す。

#### 対応サイズ

320×568 / 375×667 / 390×844 / 412×915 / 430×932 / 1080×1920 で検証済み。
どのサイズでも次を満たす:

- 横スクロール・意図しない縦スクロールなし（1 画面に収まる）
- フィールドは `width === height`（引き伸ばさない）
- TOP 10 が 10 行とも表示され、プロフィール画像も行内に収まる
- 文字が切れない（すべて `clamp()` の最小値つき）
- 横向きでは `PORTRAIT MODE REQUIRED` を出してゲームを表示しない

#### 実装上の決めごと

| 事項 | 内容 |
| --- | --- |
| 高さ | `100dvh`（`100vh` だとスマホのアドレスバーぶん下が切れる） |
| ふち | `env(safe-area-inset-*)` + 右下を少し多めに空ける（TikTok の UI と重なるため） |
| 文字・アイコン | `clamp()` の最小値つき。TOP10 の中身は行の高さ（`cqh`）から決める |
| フィールド | `aspect-ratio: 1/1` + `width: min(100%, 100cqh)` |
| 操作 | 見る専用。`touch-action: none` / `user-select: none` |
| リサイズ | 物理は時間で進むので、大きさが変わっても速さは変わらない |

### 9.1.1 レイアウト（操作画面 `index.html`）

配信には映さない。触るものを全部ここに置く。

| 区画 | 内容 |
| --- | --- |
| GAME WINDOW | `[ OPEN GAME WINDOW ]` |
| TIKTOK LIVE | LIVE の URL / @ユーザー名 と CONNECT、接続状態 |
| AUDIO | 効果音の入切・音量、BGM の MP3 選択・再生・音量 |
| TEST EVENTS | LIKE / FOLLOW / SHARE / GIFT / JOIN / COMMENT / CROWD / BOSS / SWARM / RESET |
| PREVIEW | 同じ盤面の小さい表示（音は鳴らさない） |
| GAME / ENEMIES / LIKE… | 設定スライダー（触ったその場で `config` に反映） |

設定スライダーは `js/control.js` の `SETTINGS` に 1 行足せば増える。
配信中に変えても壊れない値だけを出している（フィールドの大きさなど、
途中で変えると座標が飛ぶものは出していない）。

### 9.2 円の表示

| 要素 | 内容 |
| --- | --- |
| 中身 | TikTok プロフィール画像（取得できなければ頭文字と色） |
| 外周 | 所有者ごとの色（userId のハッシュから決定） |
| HP | 残量を外周のリングで表示（満タン時は非表示） |
| レベル | 円の内側下部にバッジ（`Lv42`、最大レベルは金色の `MAX`） |
| MAX 状態 | 虹色の回転オーラ + 残り時間の白いリング |
| 名前 | 生まれてから `ui.nameTagMs`（既定 4 秒）だけ円の下に `@ユーザー名` |

### 9.3 演出（何が起きたかを一目で分かるようにする）

いずれも**盤面を止めない**。止めるとその間ゲームが見られない。

| 出るもの | いつ | どこ | 長さ |
| --- | --- | --- | --- |
| `@ユーザー名` | 円が生まれた | 円の下 | `ui.nameTagMs` 4 秒 |
| `LIKE → Lv7` | 円が生まれた | LIVE EVENT | `ui.eventLifeMs` 9 秒 |
| `Lv12` | レベルが上がった | その場に飛ぶ | `ui.floatMs` 1.1 秒 |
| `+42` | 敵を倒した | その場に飛ぶ | 同上 |
| `+128  COMBO x5` | 連続撃破が `combo.showFrom` 以上 | その場に飛ぶ | 同上 |
| `BOSS DEFEATED` | HP が `ui.bossBarMinHp` 以上の敵を倒した | その場に飛ぶ | 同上 |
| `MAX LEVEL` | 最大レベルに届いた | その場 + LIVE EVENT | 同上 |
| `NEW RANK #7` / `RANK UP #2` | ランクイン / TOP3 内で上昇 | LIVE EVENT | 9 秒 |
| `@name #23 – 40 TO TOP10` | 直近に動いた人が TOP10 外 | TOP10 の下 | 2 秒ごとに更新 |
| `BOSS ▓▓▓░ 5,168` | 大物が居る間 | ステータス | 居る間ずっと |
| `WAVE 4` | ウェーブが進んだ | 中央のバナー | 1.8 秒 |
| `BOSS APPEARED` など | 特殊イベント | 中央のバナー | 2.2 秒 |
| `STAGE EXPANDED` | フィールドが広がる / 戻る | 中央のバナー | 2 秒 |

やらないこと（意図的に入れていない）:

- 文字を出しっぱなしにする（LIVE EVENT は 3 行・9 秒で消える）
- 画面を覆う通知（バナーは中央の小さい枠に収める）
- ランキングを点滅させる（変化した人を LIVE EVENT に 1 行出すだけ）
- 常時 BOSS（`ui.bossBarMinHp` 以上の敵が居るときだけゲージが出る）
- 演出のためにゲームを止める（すべて描画側だけで完結する）

浮かぶ文字（`renderer.float`）の大きさは**フィールド座標**で指定する。
画面 px で指定すると、スマホでは円より文字が大きくなって盤面が見えなくなる。

## 12. 中継サーバー（tikhub）

### 12.1 エンドポイント

| パス | 内容 |
| --- | --- |
| `/` | ゲーム 1 つなら本体、複数なら選択画面 |
| `/<ゲーム名>/` | 各ゲーム（`package.json` の name が URL になる） |
| `/events` | イベント配信（SSE）。ゲームが複数でも 1 本 |
| `/connect` `/disconnect` | 接続先の変更（同一 PC からのみ） |
| `/health` | 状態確認 |

### 12.2 ゲームの探索

- 起動場所から上へ 3 階層たどり、`index.html` と `js/game.js` があるフォルダを**全部**配信
- 複数見つかった場合は起動時に URL を列挙し、`/` で選択画面を出す
- `--game=<フォルダ>` で 1 つに固定できる
- `npm run update` も見つかった全ゲームを更新し、`package.json` の name で
  更新元リポジトリを判定する（取り違え防止）

### 12.3 中継サーバーの探索（ゲーム側）

1. `?bridge=` があればそれだけ
2. ページ自身のオリジン + `/events`
3. `http://127.0.0.1:8787/events` → `http://localhost:8787/events`

最後の候補は接続失敗後も開いたままにするため、ゲームを先に開いて
tikhub を後から起動しても自動で繋がる。

## 16. 用語

| 用語 | 意味 |
| --- | --- |
| 円 / circle | 視聴者が持つ実体。レベルを持ち、敵を攻撃する |
| 敵 / enemy | ゲームが自動生成する実体。撃破されるとポイントになる |
| MAX 状態 | レベル 100 到達後の 20 秒間。虹色オーラで大幅強化される |
| 燃え尽き / burnout | MAX 状態の時間切れによる消滅 |
| 順番待ち / queue | 保有上限を超えたぶんが待機する列 |
| 占有率 / coverage | 円と敵の面積の合計 ÷ 床面積。フィールド拡縮の判定に使う |
| ウェーブ / wave | 一定時間ごとに進む区切り。進んでも円とランキングは消えない |
| 操作画面 / Control Window | `index.html`。設定と接続。配信には映さない |
| ゲーム画面 / Game Window | `game.html`。9:16。配信に映す |
| ステージ | フィールドの拡大段階（0 〜 3） |
